# Project task: outperform the Numerai Classic benchmark and leading live models

**Registration, 20 November 2026.** This task proposes a v6 Jupiter 60D2L stock-ranking experiment. It has three scored milestones: beat the published benchmark on untouched offline dates, beat a prospectively selected set of leading models on the same resolved live rounds, and earn a top-ten rank on a named, fully enumerated comparison. The current project has achieved none of these milestones. The FX and Gate models predict different quantities.

## Frozen offline design

1. **Data and fitting.** Pin v6 archive identifiers, verified range/content digests, scorer source, feature names and order, and the target `target_jupiter_60`. Use only released numeric predictors. Baselines are the existing ridge and the official `lgbm_jupiter_60` predictions on identical keys. The challenger is scikit-learn histogram gradient boosting, squared error, 160 iterations, learning rate 0.05, minimum 128 samples per leaf, L2=1, early stopping disabled, seed 20261120. Fit four prespecified candidates: 8 or 128 numeric features in original schema order, each with 7 or 31 leaves. Use official training dates from 3 January 2003 through 28 December 2018; fit any imputation or scaling on training rows only. If expanded feature access is unavailable, stop and record the incomplete roster. The bounded smoke below is not one of the four confirmatory fits.
2. **Choose once.** Development selection uses all released weekly dates from 3 January 2020 through 31 December 2021. Choose the highest equal-date mean official neutral CORR; ties favor fewer features, then fewer leaves. Freeze the winning model bytes and its inference environment. Do not refit it on development or previously examined 2024 results. The terminal holdout is every available weekly date from **3 January 2025 through 26 June 2026 inclusive**, identified from metadata before acquiring labels. Confirm with the project that neither these targets nor their per-model scores have already informed selection. Otherwise advance to a prospectively sealed, dated replacement before any access. The announced dates are not guaranteed to be untouched by unrelated research.
3. **Leakage checks.** Establish that each source was available as of each forecast, the whole 60-business-day target plus two lag days cleared before the next partition, and the last dated label is fully mature. Require unique native ticker/date keys and exact full-universe alignment across predictions, benchmark, targets and 300 official neutralizer exposures. Give exclusions by reason before seeing scores. Do not feed benchmark predictions, neutralizers or future target columns into the challenger. Shared tickers across dates are part of the task. Cluster inference by time rather than treating those rows as independent observations. [Numerai Classic data](https://docs.numer.ai/numerai-tournament/data)
4. **Primary offline gate.** Freeze a date-indexed manifest of all challenger predictions before unlocking outcomes. For each date, use the pinned official neutral scoring implementation on the same stocks, same target, same exposures and unit sample weights for both submissions. Report mean paired neutral-CORR improvement over `lgbm_jupiter_60`. Passing requires positive absolute challenger mean, a positive lower limit of the preregistered 95% interval for the paired improvement, and positive mean improvement under the raw CORR secondary check. Use 10,000 circular moving-block bootstrap resamples of consecutive weekly dates, block length 13, seed 20261120. Publish a 26-week sensitivity, coverage, the worst 13-week block and effective block count. A small number of blocks materially limits confidence. One terminal evaluation is permitted for this registration. A subsequent revision requires a new frontier. ## Prospective peer challenge and top-ten condition

**Freeze peers before the round opens.** Save a public, timestamped Classic model-board response with the metric explicitly set to the official default MMC60 reputation. Select the first ten eligible model IDs by provider rank, recording ties and ordering. Keep that cohort fixed for the first 12 successive Saturday Classic rounds after the freeze; never replace an absent peer with a weaker model. Log all 12 including missed, late or unresolved rounds. This challenges established models selected by a historical reputation measure using a separate, forward-looking scoring measure. [Numerai Classic API](https://docs.numer.ai/numerai-tournament/api)

**Primary live endpoint.** For each eligible round, require the same Jupiter 60D2L target, neutralizer regime and raw metric versions for every model, final day 60, and official resolved status. Freeze the selection formula `S = 8 × NCORR + 32 × NMMC`. These are raw score weights for the configured comparison; S is neither a token payout nor the default global model reputation. Read the actual configuration for each round. On a configuration change, close this series and register the next comparison separately. The paired leading-peer milestone requires complete final scores for all ten peers and the challenger on all 12 rounds, and challenger mean S strictly greater than the mean S of **each** of the ten peers. Report paired deltas, per-metric results, ties and coverage. The successive 60-day targets overlap, so the 12 rounds are descriptive evidence of that scored period. [Numerai Classic neutral scores and resolution](https://docs.numer.ai/numerai-tournament/scoring)

**What counts as top ten.** For a resolved-round claim, paginate the complete eligible same-round Classic model field with both official raw scores. Deduplicate model IDs, reconcile field size against provider metadata, and log missing and late submissions. Rank using S descending. Conservatively count peers tied with the challenger ahead of it. Require complete score coverage or a provable worst-case rank at most 10 after counting every missing eligible peer ahead. Record the field denominator. Call this “top ten by registered weighted score in round R.” A claim of a top-ten **official global leaderboard** position separately requires the provider's model-level rank at most 10 with its exact sort, timestamp and reputation eligibility. Neither beating the one offline benchmark nor beating ten selected peers alone establishes either rank.

**Submission condition.** A top-ten-only submission request remains blocked until independently supported by like-for-like pre-submission evidence and the designated account and model slot are available for the authorized upload. Before cutoff one can privately hash a complete live prediction vector and later score a shadow NCORR if aligned targets/neutralizers are released. Official NMMC also needs the contemporaneous Classic Meta Model and an officially scored submission. The current cache provides neither prospective peer predictions nor that Meta Model. If the condition literally means a verified official top-ten rank before a first submission, it cannot be certified in advance. A separately authorized unstaked evaluation submission would enable prospective scoring; it is a different permission and is not assumed by this task. A late upload, private diagnostic or modeled NMMC is insufficient. [Numerai submission windows and format](https://docs.numer.ai/numerai-tournament/submissions) · [Classic scoring definitions](https://docs.numer.ai/numerai-tournament/scoring)
